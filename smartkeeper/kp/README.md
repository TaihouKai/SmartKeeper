# `kp`

上下文构造、prompt、各种 LLM 调用和裁定管线。只依赖 `engine` 和 `llm` 的接口；给 LLM 的对局内容全部经由 engine 的读取接口。

- `context.py`：每种调用的上下文构造，各自只取最小必要上下文。反馈撰写只看该玩家的结果、他看到的别人的行为、公共事件、推进时间和他自己的历史视图。
- `prompts/`：每种调用一个模板（中文维护，模板里指定 KP 的输出语言）。
- `pipeline.py`：`KP` 类。`run_round`：声明核对 → 检定与空间查询规划 → 引擎掷骰与查询 → 裁定（解析或校验失败带着错误重试，最多 2 次，仍失败则回合停在待审核）→ 各玩家反馈并行撰写 → 泄密检查（M5 之前是直接通过的占位）→ 非审核模式下自动发布 → 给新感知到的实体起代号。
- 裁定里提到实体一律写 `{{实体ID}}`，反馈撰写前按读者自己的代号替换，读者不认识的显示成“某人”。
- 玩家文本在 prompt 里一律包进 `<player_text>` 标签，尖括号转义。
- 单独测试：`uv run pytest tests/kp`（FakeLLM 加内存 engine）
